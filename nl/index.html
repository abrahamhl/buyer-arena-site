Vijf panels, vijf doelen

Een lancering mislukt om verschillende redenen, afhankelijk van wie er kijkt. Elk panel zoekt zijn eigen problemen en onderbouwt de score met bewijs.

users

Eindgebruikers

Waar gaan conversies verloren, en waarom?

  • Echte klantreizen in de browser door synthetische klanten.
  • Trechter per stap, gevonden frictie en uitval.
  • A/B-vergelijking van twee versies van je site.
developers

Ontwikkelaars

Hoe snel boekt een nieuwkomer een eerste succes?

  • Kloont de repository en volgt de README letterlijk.
  • Installeert en draait tot het eerste werkende resultaat.
  • Meet de tijd tot het eerste succes en noteert wat er breekt.
investors

Investeerders

Wat zegt het bewijs tegen iemand die due diligence doet?

  • Probleem, onderscheidend vermogen en passend verdienmodel: open source, open core, SaaS, abonnement, diensten of API.
  • Viraal potentieel en strategische interesse: AI-labs, browserautomatisering, analytics en A/B-testen, platforms voor ontwikkeltools, beveiliging.

Signalen, nooit een voorspelling van financiering.

security

Red team

Waar komt iemand met kwade bedoelingen binnen?

  • Geheimen, afhankelijkheden, injectie in CI-scripts en installatiescripts.
  • Het aanvalsoppervlak van de website via Argus, privacy en cookies.
  • Het aanvalsoppervlak voor AI-agents: promptinjectie in skills, AGENTS.md en documentatie, verborgen Unicode, vergiftigde MCP-tools en gevaarlijke toolrechten, onbetrouwbare webinhoud die naar een LLM gaat, te ruime agentrechten.
segments

Segmenten

Werkt het voor mensen die niet op je team lijken?

  • Objectieve doelgroepen, geen stereotypen.
  • Toegankelijkheid, trage verbindingen, 200 % zoom en mobiel.
  • Mensen die geen account willen aanmaken, en andere talen.

Elke score is bewijs

Geen score zonder bron. Elke controle zegt waar hij vandaan komt.

  • 0–5 sterren en 0–100 % per panel en per controle.
  • Elke controle verwijst naar bestand:regel, een URL of een opgenomen gebeurtenis in de klantreis.
  • Exporteert naar CSV, PNG, JPG, Markdown, JSON en PDF.
  • Rapport in het Spaans, Engels en Nederlands.

Aan de slag

Je hebt Node.js 22.12 of nieuwer en Git nodig. De demo downloadt eenmalig Chromium voor Playwright.

  1. 1
    Kloon de repository
    git clone https://github.com/abrahamhl/buyer-arena.git
  2. 2
    Ga naar de map
    cd buyer-arena
  3. 3
    Installeer de afhankelijkheden
    npm install
  4. 4
    Draai de demo en open het rapport dat hij maakt
    npm run demo
  5. 5
    Open de lokale visuele controlekamer
    npm run ba -- studio
  6. 6
    Audit je eigen product: pas de URL en de tekst aan die succes betekent
    npm run ba -- launch-check --repo . --url https://your-site.example --success-text "welcome"

Via je telefoon

Geen computer nodig: de audit draait op GitHub Actions.

  1. 1Open de GitHub-app.
  2. 2Ga naar de repository abrahamhl/buyer-arena (of je fork).
  3. 3Open Actions en kies Launch check.
  4. 4Tik op Run workflow en vul de URL en de mix in.
  5. 5Het resultaat verschijnt als samenvatting met sterren op de runpagina, met een rapport om te downloaden.
Open de workflow „Launch check”

Gebruik het vanuit AI-agents

Buyer Arena heeft een MCP-server, zodat een agent audits kan starten en de resultaten kan lezen.

npm run ba -- mcp

Standaard luistert hij alleen op localhost. Openstellen voor een netwerk is een bewuste keuze van jou.

Veiligheid en privacy

Een tool die websites test, mag zelf geen risico worden.

  • Draait lokaal

    Op je eigen machine of je eigen CI-runner. Geen dienst ertussen.

  • Alleen jouw origin

    Bezoekt alleen de origin die je opgeeft.

  • Blokkeert derden

    Verzoeken naar andere hosts worden tijdens klantreizen geblokkeerd.

  • Geen echte betaalgegevens

    Vult nooit een kaart of echte betaalgegevens in.

  • Tests kosten niets

    De testsuite doet nul betaalde API-aanroepen.

  • Eén bestand

    Het rapport is één HTML-bestand dat offline werkt.
