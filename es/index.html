Cinco paneles, cinco intenciones

Un lanzamiento falla por motivos distintos según quién mire. Cada panel busca lo suyo y lo puntúa con evidencia.

users

Personas usuarias

¿Dónde se pierden las conversiones y por qué?

  • Recorridos reales en navegador hechos por clientela sintética.
  • Embudo paso a paso, fricción detectada y abandono.
  • Comparación A/B entre dos versiones de tu web.
developers

Desarrollo

¿Cuánto tarda una persona recién llegada en conseguir su primer éxito?

  • Clona el repositorio y sigue el README al pie de la letra.
  • Instala y ejecuta hasta el primer resultado que funciona.
  • Mide el tiempo hasta el primer éxito y anota qué se rompe.
investors

Inversión

¿Qué dice la evidencia a quien hace la due diligence?

  • Problema, diferenciación y encaje del modelo de negocio: código abierto, open core, SaaS, suscripción, servicios o API.
  • Potencial de viralidad e interés estratégico: laboratorios de IA, automatización de navegador, analítica y A/B, plataformas para desarrollo, seguridad.

Son señales, nunca una predicción de financiación.

security

Equipo rojo

¿Por dónde entraría alguien con malas intenciones?

  • Secretos, dependencias, inyección en scripts de CI y scripts de instalación.
  • Superficie de la web con Argus, privacidad y cookies.
  • Superficie de ataque para agentes IA: inyección de prompts en skills, AGENTS.md y documentación, Unicode oculto, envenenamiento de herramientas MCP y capacidades peligrosas, contenido web no fiable que llega a un LLM y permisos de agente demasiado amplios.
segments

Segmentos

¿Funciona para quien no se parece a tu equipo?

  • Públicos objetivos, no estereotipos.
  • Accesibilidad, conexiones lentas, zoom al 200 % y móvil.
  • Personas que no quieren crear una cuenta, y otros idiomas.

Cada nota es evidencia

Nada de puntuaciones sin respaldo. Cada comprobación dice de dónde sale.

  • 0–5 estrellas y 0–100 % por panel y por comprobación.
  • Cada comprobación cita archivo:línea, una URL o un evento del recorrido grabado.
  • Exporta a CSV, PNG, JPG, Markdown, JSON y PDF.
  • Informe en español, inglés y neerlandés.

Empezar

Necesitas Node.js 22.12 o superior y Git. La demo descarga una vez Chromium para Playwright.

  1. 1
    Clona el repositorio
    git clone https://github.com/abrahamhl/buyer-arena.git
  2. 2
    Entra en la carpeta
    cd buyer-arena
  3. 3
    Instala las dependencias
    npm install
  4. 4
    Ejecuta la demo y abre el informe que genera
    npm run demo
  5. 5
    Abre la sala de control visual en local
    npm run ba -- studio
  6. 6
    Audita tu propio producto: cambia la URL y el texto que indica éxito
    npm run ba -- launch-check --repo . --url https://your-site.example --success-text "welcome"

Desde el móvil

Sin ordenador: la auditoría corre en GitHub Actions.

  1. 1Abre la app de GitHub.
  2. 2Ve al repositorio abrahamhl/buyer-arena (o tu copia).
  3. 3Entra en Actions y elige Launch check.
  4. 4Pulsa Run workflow y rellena la URL y la mezcla.
  5. 5El resultado aparece como resumen con estrellas en la página de la ejecución, con el informe para descargar.
Abrir el flujo «Launch check»

Úsalo desde agentes IA

Buyer Arena incluye un servidor MCP para que un agente lance auditorías y lea los resultados.

npm run ba -- mcp

Escucha solo en localhost por defecto. Abrirlo a la red es una decisión explícita tuya.

Seguridad y privacidad

Una herramienta que prueba webs no debería convertirse en un riesgo.

  • Corre en local

    En tu máquina o en tu propio runner de CI. No hay servicio intermedio.

  • Solo el origen que indicas

    Visita únicamente el dominio que le das.

  • Bloquea terceros

    Las peticiones a otros dominios se bloquean durante los recorridos.

  • Nunca datos de pago reales

    Jamás introduce una tarjeta ni datos de pago reales.

  • Tests sin coste

    La batería de tests hace cero llamadas a APIs de pago.

  • Un solo archivo

    El informe es un HTML que funciona sin conexión.
