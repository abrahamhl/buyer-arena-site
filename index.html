Five panels, five intents

A launch fails for different reasons depending on who is looking. Each panel looks for its own problems and scores them with evidence.

users

End users

Where are conversions lost, and why?

  • Real browser journeys by synthetic customers.
  • Step-by-step funnel, detected friction and drop-off.
  • A/B comparison of two versions of your site.
developers

Developers

How long until a newcomer gets a first success?

  • Clones the repository and follows the README to the letter.
  • Installs and runs until the first working result.
  • Measures time-to-first-success and records what breaks.
investors

Investors

What does the evidence tell someone doing due diligence?

  • Problem, differentiation and business-model fit: open source, open core, SaaS, subscription, services or API.
  • Virality potential and strategic interest: AI labs, browser automation, analytics and A/B testing, dev-tool platforms, security.

Signals, never a funding prediction.

security

Red team

Where would someone with bad intentions get in?

  • Secrets, dependencies, CI script injection and install scripts.
  • Website surface via Argus, privacy and cookies.
  • The AI-agent attack surface: prompt injection in skills, AGENTS.md and docs, hidden Unicode, MCP tool poisoning and dangerous tool capabilities, untrusted web content fed to LLMs, over-broad agent permissions.
segments

Segments

Does it work for people who are not like your team?

  • Objective audiences, not stereotypes.
  • Accessibility, slow connections, 200 % zoom and mobile.
  • People who refuse to create an account, and other languages.

Every score is evidence

No score without a source. Every check says where it comes from.

  • 0–5 stars and 0–100 % per panel and per check.
  • Each check cites a file:line, a URL or a recorded journey event.
  • Exports to CSV, PNG, JPG, Markdown, JSON and PDF.
  • Report in Spanish, English and Dutch.

Choose the mix

You decide how much attention each panel gets. Before a funding round: more investors, less red team. Before open-sourcing: the other way round.

Example: preparing a funding round

  • End users35 %
  • Developers15 %
  • Investors30 %
  • Red team5 %
  • Segments15 %

Depth

quick Quick
Fewer participants and shorter journeys. A check before every deploy.
standard Standard
The default. Enough to decide whether to launch.
deep Deep
More journeys and more steps per journey. For a major launch.

Get started

You need Node.js 22.12 or later and Git. The demo downloads Chromium for Playwright once.

  1. 1
    Clone the repository
    git clone https://github.com/abrahamhl/buyer-arena.git
  2. 2
    Enter the folder
    cd buyer-arena
  3. 3
    Install the dependencies
    npm install
  4. 4
    Run the demo and open the report it writes
    npm run demo
  5. 5
    Open the local visual control room
    npm run ba -- studio
  6. 6
    Audit your own product: change the URL and the text that means success
    npm run ba -- launch-check --repo . --url https://your-site.example --success-text "welcome"

From your phone

No computer needed: the audit runs on GitHub Actions.

  1. 1Open the GitHub app.
  2. 2Go to the repository abrahamhl/buyer-arena (or your fork).
  3. 3Open Actions and choose Launch check.
  4. 4Tap Run workflow and fill in the URL and the mix.
  5. 5The result appears as a summary with stars on the run page, with a downloadable report.
Open the “Launch check” workflow

Use it from AI agents

Buyer Arena ships an MCP server so an agent can start audits and read the results.

npm run ba -- mcp

It listens on localhost only by default. Exposing it to a network is an explicit choice you make.

Safety and privacy

A tool that tests websites should not become a risk itself.

  • Runs locally

    On your machine or your own CI runner. No service in between.

  • Only your origin

    It visits only the origin you give it.

  • Blocks third parties

    Requests to other hosts are blocked during journeys.

  • No real payment data

    It never enters a card or any real payment details.

  • Tests cost nothing

    The test suite makes zero paid API calls.

  • One file

    The report is a single HTML file that works offline.
